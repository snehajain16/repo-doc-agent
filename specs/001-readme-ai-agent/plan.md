## Agent Loop Design

The agent uses Claude's tool-use API in a `while` loop until Claude returns a response with no tool calls (i.e. it has enough context to generate the README).

```
User prompt → Claude (with tools) → tool_call → tool_result → Claude → ... → final text output
```

**System prompt** gives Claude:
- The list of available tools and when to use them
- The target README structure (sections to populate)
- Instructions to be specific and accurate (no generic filler)
- A budget hint: explore thoroughly but stop after ~15 tool calls

**Tools provided to Claude:**
| Tool | Signature | Description |
|---|---|---|
| `list_files` | `(path: str) -> list[str]` | List files/dirs at path within repo |
| `read_file` | `(path: str) -> str` | Read file content (truncated at 8000 chars) |
| `search_code` | `(pattern: str) -> list[dict]` | Grep pattern, returns `{file, line, content}` |
| `detect_language` | `() -> dict` | Returns `{primary, others, frameworks}` |
| `read_dependency_file` | `() -> dict` | Parses deps from lockfiles/manifests |

**Structured output:** Claude returns a JSON object matching `ReadmeData` (Pydantic model) which the renderer converts to Markdown via Jinja2.

## Data Models

```python
class ReadmeData(BaseModel):
    project_name: str
    description: str
    features: list[str]
    prerequisites: list[str]
    installation: list[str]           # ordered steps
    usage_examples: list[UsageExample]
    configuration: list[ConfigItem]
    contributing: str | None
    license: str | None
    badges: list[Badge]

class UsageExample(BaseModel):
    description: str
    code: str
    language: str

class ConfigItem(BaseModel):
    name: str
    description: str
    default: str | None
    required: bool

class Badge(BaseModel):
    label: str
    url: str
```

## GitHub Action Flow

```
on: push (main)
    ↓
Checkout repo
    ↓
Run readme-agent generate (python -m readme_agent.cli)
    ↓
If README changed → commit via GitHub API
    ↓
Done (no git binary needed in runner)
```

---

## Security Considerations

- Anthropic API key only from `$ANTHROPIC_API_KEY` env var.
- GitHub token only from `$GITHUB_TOKEN` (auto-provided by Actions).
- All `read_file` / `list_files` calls validate path is inside `repo_root` (no `..` traversal).
- No user input passed unsanitised to shell commands.
